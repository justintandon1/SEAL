SEAL precision comparison

Math uses Andwwy/SEAL; code uses Andwwy/v_code-SEAL. This separates vector construction from evaluation and explains the Transformers 4 versus 5 effect.

Short answer: Both published steering vectors are FP32. Transformers 4 versus 5 matters when the dtype is omitted: the old math path resolves to FP32, while Transformers 5 may use the checkpoint's BF16 dtype. The code path avoids this drift by explicitly requesting FP32 and asserting it.

What changes under Transformers 5?

  • Unspecified dtype: the DeepSeek checkpoint can load as BF16 instead of the FP32 behavior used by the original math extraction.
  • Performance: BF16 generally uses about half the weight memory and runs faster.
  • Numerics: hidden activations and the steering vector change slightly. Whether evaluation accuracy changes materially must be measured.
  • Explicit FP32: precision should remain aligned, but this repository still excludes v5 because Transformers/vLLM API compatibility is not guaranteed.

Reproduction recommendation

Use the repository's pinned Transformers 4 environment. If testing v5, explicitly request FP32 during extraction and steering evaluation, then verify next(model.parameters()).dtype == torch.float32. Do not compare an FP32 reference run with an accidental BF16 rebuild as if they were the same experiment.
