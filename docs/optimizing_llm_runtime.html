Optimizing LLM Runtime

What the LM head is, and how three small changes to SEAL's hidden-state extraction cut gigabytes of wasted GPU memory — explained from zero, then line by line in the real code.

A language model does exactly one thing: guess the next word.
The LM head is the part that makes the guess. Everything before it just prepares for that moment.

1. A language model has two parts

Think of the model as a reader followed by a guesser:

input
"The capital of France is"
the text so far
→
part 1 · the reader
Transformer layers
28 layers read the text and build up understanding
→
what comes out
One vector
1,536 numbers summarizing "what should come next"
→
part 2 · the guesser
LM head
turns that vector into a score for every word it knows
→
output
"Paris" 🏆
highest-scoring word wins

The reader's output — that vector of 1,536 numbers — is the model's internal "thought." It isn't a word yet. It's a point in a huge abstract space that means something like "a French capital city should come next." Somebody has to translate that thought into an actual word. That translator is the LM head.

2. The LM head is just a giant scorecard

Here's the whole trick. The model's vocabulary has ~152,000 words (tokens). The LM head stores one row of 1,536 numbers for every word — you can think of each row as that word's "direction" or fingerprint in the same space the thought lives in.

To make its guess, the LM head compares the thought against every row, one by one. Each comparison is a dot product: multiply the numbers pairwise and add them up. If the thought and a word's row point the same way, the score is high. That's it — no magic, just 152,000 similarity checks:

the thought
(1,536 numbers)
·
⋮   151,930 more rows   ⋮
the LM head: one row per word
=
⋮
one score per word
("logits")

So when people say the LM head is "a linear layer," this is all they mean: one matrix multiplication — thought vector × word matrix → 152,000 scores. The scores are called logits; a softmax then squashes them into probabilities.

3. Try it yourself

Below is a miniature LM head with a 4-number thought and 5 words in its vocabulary. The four sliders are the thought vector. Each candidate word has its fixed row of 4 numbers (shown on hover). Drag the sliders and watch the dot products — and the winning word — change.

"The capital of France is Paris"
Real models work the same way, except the thought has 1,536 dimensions instead of 4 — and they aren't neatly labeled like "France-ness"; the model invents its own dimensions during training. Try dragging food-ness up: the same sentence starts predicting croissant. That's literally how sampling weirdness happens.

4. Why it matters: this thing is huge

For the model in this project (DeepSeek-R1-Distill-Qwen-1.5B), the LM head is one matrix of 1,536 × 151,936 numbers:

~233M
parameters in this single layer — a sizable slice of a "1.5B" model
151,936
scores produced per token position — one for every word it knows
~0.6 MB
memory for one position's scores (fp32). Sounds small…
~6 GB
…but score a 10,000-token trace at every position and it's gigabytes

During generation that cost is unavoidable — the model must score every word to pick the next one, for every single token it writes. But our steering-vector extraction feeds an already-finished reasoning trace back through the model just to record the layer-20 "thoughts." There is no next word to guess. That observation is worth gigabytes — as the real code below shows.

5. The original code, line by line

This is the extraction loop from SEAL's original hidden_analysis.py (the generate() function). It works, but on a 24 GB GPU it crashes with CUDA out of memory on long traces, and its output file hidden.pt fills the disk. Red lines are where the waste happens.

hidden_analysis.py · ORIGINAL
1def generate(model_path, data, save_dir): Takes the model name, the finished reasoning traces, and where to save the result.
2 model = AutoModelForCausalLM.from_pretrained(model_path, device_map="auto") Loads the whole model onto the GPU — reader and LM head — in full fp32 precision (~7 GB of weights).
3 prompts = [d["prompt"] + d["response"] for d in data] Each input = the question plus the model's already-written answer. Nothing new will be generated.
4 layer_num = model.config.num_hidden_layers + 1 29 sets of hidden states: the embeddings plus one after each of the 28 layers.
5 hidden_dict = [{} for _ in range(layer_num)] One storage dict per layer — foreshadowing: it will save all 29 even though only layer 20 is ever used.
6 for k, p in tqdm(enumerate(prompts), total=len(prompts)): Loop over traces one at a time; tqdm just draws a progress bar.
7 tokenized_batch = tokenizer([p], return_tensors="pt", padding=True) Turn the text into token IDs — a PyTorch tensor, "batch" of one.
8 tokenized_batch = {k: v.to(model.device) for k, v in tokenized_batch.items()} Ship those tensors to the GPU where the model lives.
9 with torch.no_grad(): "We're only reading, not training" — skips gradient bookkeeping, which would otherwise more than double memory.
10 output = model(**tokenized_batch, output_hidden_states=True) Waste #1 — the big one. Calling the full model runs the LM head at every position: a [1 × seq_len × 151,936] logits tensor (~6 GB for a 10k-token trace) that nothing ever reads. It also builds the KV cache (use_cache defaults to on) — more memory that only generation needs.
11 hidden_states = output.hidden_states The part we actually want: 29 tensors, each [1 × seq_len × 1,536] — the "thoughts" at every layer.
12 hidden_states = [h.detach().cpu() for h in hidden_states] Waste #2. Copies all 29 layers of full-sequence hidden states to CPU RAM, even though the steering vector only ever uses layer 20.
13 step_index, check_index, switch_index = generate_index(p, tokenizer, split_id, ...) Find where each reasoning step starts (paragraph breaks inside <think>), and which steps are "wait, let me check" / "alternatively" moments.
14 step_index = torch.LongTensor(step_index) # (same for check/switch) Convert those position lists to tensors so they can be used as indexes.
15 for i in range(layer_num): Waste #3. Stores step vectors for every one of the 29 layers…
16 h = hidden_states[i][0] Layer i's hidden states; [0] = the only sequence in our batch of one.
17 step_h = h[step_index] Keep only the vectors at step-start positions — a few dozen per trace.
18 hidden_dict[i][k] = {"step": step_h, "check_index": ..., "switch_index": ...} File them away per layer, per trace.
19 del hidden_states Free the big tensors before the next trace.
20 torch.save(hidden_dict, f"{save_dir}/hidden.pt") …so hidden.pt is 29× bigger than needed. On the Vast machine this filled the disk.

6. The optimized code, line by line

Same function after the fixes (this is the version that ran the GSM8K smoke test in PR #5). Only the green lines changed — everything else is identical. Three changes, each attacking one waste:

hidden_analysis.py · OPTIMIZED
1def generate(model_path, data, save_dir, keep_layers=None): Change #1a. New argument: the caller can say "I only need layer 20" (keep_layers=[20]).
2 if keep_layers is None: …
3 keep_layers = list(range(layer_num)) If the caller doesn't ask, keep all 29 layers — old behavior, so nothing else breaks.
4 for k, p in tqdm(enumerate(prompts), total=len(prompts)): Same loop as before.
5 tokenized_batch = tokenizer([p], return_tensors="pt", padding=True) Same tokenization.
6 tokenized_batch = {k: v.to(model.device) for k, v in tokenized_batch.items()} Same move to GPU.
7 with torch.no_grad(): Same "reading, not training."
8 base_model = getattr(model, "model", model) Change #2 — the LM head skip. The loaded object is a wrapper: model.model is the reader (transformer), model.lm_head is the guesser. This line says "give me just the reader." getattr(…, model) = if there's no .model attribute (different architecture), fall back to the full model instead of crashing.
9 output = base_model(**tokenized_batch, output_hidden_states=True, use_cache=False) Changes #2 + #3. Calling base_model means the 6 GB logits tensor is never created — the forward pass stops at the hidden states (which are identical either way; the LM head runs after them). use_cache=False also skips building the KV cache, which only matters when generating new tokens.
10 hidden_states = output.hidden_states Same 29 thought tensors — note they stay on the GPU for now (no bulk copy of all layers).
11 step_index, check_index, switch_index = generate_index(p, tokenizer, split_id, ...) Same step detection.
12 for i in keep_layers: Change #1b. Only visit the layers the caller asked for — for us, just layer 20 instead of all 29.
13 h = hidden_states[i][0].detach().cpu() Change #1c. The CPU copy moved inside the loop: only the kept layer(s) ever leave the GPU, instead of all 29.
14 step_h = h[step_index] Same slicing of step-start vectors.
15 hidden_dict[i][k] = {"step": step_h, "check_index": ..., "switch_index": ...} Same storage.
16 del hidden_states Same cleanup.
17 torch.save(hidden_dict, f"{save_dir}/hidden.pt") Unchanged line, but with keep_layers=[20] the file is now ~29× smaller — the disk-full crash is gone too.

7. What each change buys

ChangeLineWhat it eliminatesRough saving (10k-token trace)
getattr(model, "model", model)8–9 The logits tensor — 151,936 next-word scores at every position that nobody reads ~6 GB GPU per forward pass
use_cache=False9 The KV cache (per-layer attention memory used only for generating new tokens) ~1–2 GB GPU
keep_layers=[20]1, 12, 13 Storing and saving 28 layers of hidden states that the steering vector never uses ~29× smaller hidden.pt + less CPU RAM

The key insight behind all three: know which part of the pipeline your task actually needs. Generation needs the guesser and the cache; extraction only needs the reader's thoughts at one layer. The output is bit-identical — hidden states are produced before the LM head ever runs — so this is pure waste removal, not an approximation.

One-line summary: the LM head turns the model's internal "thought" vector into 152,000 next-word scores — essential when writing text, pure waste when you only want the thoughts. Skipping it (plus the cache and the unused layers) is the difference between crashing a 24 GB GPU and finishing the run.
