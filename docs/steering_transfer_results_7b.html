SEAL · Reasoning Steering · 7B Scale-Up

Scaling math & code steering vectors to DeepSeek-R1-Distill-Qwen-7B

A steering vector extracted from the MATH training set (layer 20, coefficient α = −1.0, 500 correct + 500 incorrect traces) on DeepSeek-R1-Distill-Qwen-7B — the same recipe used for the 1.5B model's six-benchmark transfer report, rebuilt from scratch at 7B scale, plus a second vector built the same way from APPS (code) traces instead of MATH ones. This report covers both vectors' in-domain and cross-domain results on MATH-500 and APPS in full; logic (LogiQA) has a baseline (51.4% accuracy) but the steered run is still pending.

Result: on MATH-500, the MATH vector raised accuracy from 84.4% to 87.8% (+3.4 points) while cutting average reasoning tokens by 17.9%. Applied cross-domain to APPS (code), it raised pass@1 from 28.4% to 32.8% (+4.4 points, +15.5% relative). The reverse direction is even more striking: an APPS-derived vector, applied cross-domain to MATH-500, raised accuracy from 84.4% to 89.2% (+4.8 points) — outperforming the in-domain MATH vector on its own benchmark. In-domain, the APPS vector also improves its own home benchmark (28.4% → 33.0% pass@1, +4.6 points) — slightly less than it helps MATH-500 cross-domain, reinforcing that this isn't just an in-domain effect. Steering directions transfer well across math and code in both directions.

Methodology. Vector extracted from data/MATH/train.jsonl (7,500 problems, all generated at max_tokens=10000; 85.6% baseline generation accuracy), pooling the first 500 correct and first 500 incorrect traces' layer-20 hidden states at each \n\n reasoning-step boundary inside <think>. Steering vector = mean(check ∪ switch) − mean(other), applied by adding coef × vector at layer 20 with coef = −1.0. Evaluated on a random 500-example draw from MATH-500 (seed 42), identical baseline/steered prompts and decoding settings. The APPS-derived vector uses the identical recipe, layer, and coefficient — the only difference is its source data: 500 correct + 500 incorrect traces generated on the APPS train split (via vLLM, 1,500 problems attempted to reach that split given APPS's much lower ~38% pass rate), with code-domain reasoning-step keywords in place of math ones. Vector shape [3584], norm 78.8.
  • Model: deepseek-ai/DeepSeek-R1-Distill-Qwen-7B (hidden_size 3584, 28 layers — same depth as the 1.5B model, ~2.3x the width).
  • Vector shape confirmed [3584], norm 82.4.
  • Both models use layer 20 unchanged — the 1.5B→7B jump is almost entirely in width, not depth, so the same relative layer applies.
  • APPS uses pass@1 (generated code passes all test cases) as its accuracy-equivalent metric, evaluated on a random 500-example draw from the APPS test split (seed 42) with the same vector, layer, and coefficient as MATH-500 — no code-specific retuning. Token counts for the APPS run haven't been pulled yet.
